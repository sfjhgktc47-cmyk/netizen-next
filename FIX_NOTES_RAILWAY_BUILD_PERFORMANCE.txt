Фикс Railway build после оптимизации скорости.

Причина ошибки:
- В прошлом архиве публичным страницам был поставлен `export const revalidate = 60`.
- Из-за этого Next.js пытался пререндерить /catalog, /product и API во время `npm run build`.
- Во время build Railway не всегда имеет доступ к `postgres.railway.internal`, поэтому Prisma падала на этапе сборки.

Что исправлено:
- Публичные страницы снова переведены в `export const dynamic = "force-dynamic"`.
- Next.js больше не должен лезть в базу при сборке публичных страниц.
- Кэширование запросов к БД через `unstable_cache` из прошлого фикса сохранено.
- Cache-Control для публичных API сохранён.

Итог:
- build не должен падать из-за недоступной БД;
- runtime-ускорение публичного каталога и главной остаётся.
